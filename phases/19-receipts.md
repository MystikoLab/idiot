# Phase 19 — Receipt attachments with OCR

A transaction can carry several receipts (images and PDFs). Receipts are added in the add / edit form, scanned on device with Vision, and the detected amount, merchant and date are offered back to the form.

## Implementation guide

- **Model** (`Models/Attachment.swift`): `Attachment` with `id`, `filename`, `contentType` (UTType identifier), `data` (`@Attribute(.externalStorage)`, optional), `createdAt`, `syncStamp`, `transaction: Transaction?`. `Transaction.attachments: [Attachment]?` is the inverse with delete rule `.cascade`. `Transaction.hasAttachments` only counts the relationship and never touches `data`. `Attachment.self` is registered in the single `ModelContainer` in `idiotApp.swift` (widgets and MCP reuse that container or a snapshot). "Erase All Data" deletes attachments, Force Push touches their `syncStamp`.
- **Storage** (`Helpers/AttachmentProcessor.swift`): `AttachmentProcessor.process` turns raw data into a `ReceiptFile` value (id, filename, content type, data). Images are downscaled with ImageIO to a 2000 px long edge (orientation applied) and re-encoded as JPEG at 0.7; PDFs (detected by the `%PDF-` header) are stored untouched. The same file holds `ReceiptImporter` (file URLs, raw data, `NSItemProvider`s, the pasteboard) and `ReceiptPreview` (writes temp files for Quick Look). All of it is `nonisolated` and runs in detached tasks.
- **OCR** (`Helpers/ReceiptScanner.swift`): `ReceiptScanner.scan(_:)` runs off the main actor. Images go through `VNRecognizeTextRequest` (accurate); fragments on the same visual row are joined left to right so "TOTAL" and its value end up on one line. PDFs use the PDFKit text of page one and fall back to rendering the page and running Vision. `parse(lines:)` returns:
  - amount: the value on (or right below) a line with "grand total" / "amount due" / "balance due" / "total due" (preferred) or "total", skipping subtotal and tax / discount / item-count totals; otherwise the largest value with two decimals. Both `1,234.56` and `1.234,56` are read.
  - title: the first mostly-alphabetic line in the top eight that is not an amount, a date, a URL / e-mail or a generic word such as "Receipt". All-caps names are capitalized.
  - date: ISO, numeric (day / month order follows the locale when ambiguous) and month-name formats; future dates and dates older than ten years are ignored.
- **Form** (`Views/ReceiptsSection.swift`, `Views/TransactionFormView.swift`): the form keeps `receipts: [ReceiptFile]` in state for both add and edit and writes the models on Save (`saveReceipts`), so Cancel discards additions and removals. The "Receipts" section shows thumbnails (tap for Quick Look, x button or context menu to remove) and an "Add Receipt" menu: Choose File (`fileImporter`, images + PDFs, multiple), Photo Library (`PhotosPicker`, images), Scan Document (iOS, `VNDocumentCameraViewController`, one attachment per page) and Paste (`NSPasteboard` / `UIPasteboard`). On macOS `receiptImportTarget` adds file / image drops on the form, ⌘V when the form itself has focus, and `importsItemProviders` with `ImportFromDevicesCommands` (File > Import from iPhone or iPad) for Continuity Camera.
- **Applying a scan**: each added receipt is scanned. An empty amount or title field is filled directly; a detected value that differs from what is already there, and any detected date on another day, becomes a chip under the section ("Amount 42.50", "Title Costco", "Date 12 Nov") that applies on tap and can be dismissed. A filled title goes through the normal `title` state, so title suggestions and auto-categorization react once, exactly as for typed text. Nothing is shown when nothing is detected.
- **List** (`Views/TransactionRowView.swift`, `Views/TransactionListView.swift`): rows show a paperclip next to the title when `hasAttachments`. The context menu has "View Receipts" (Quick Look over all receipts) when there are any; it is read-only and also works on locked past-month rows. Adding and removing only happens in the form, which stays unreachable for locked rows.
- Pending receipts are not part of the saved form draft. CSV, MCP tools and widgets have no attachment support. `NSCameraUsageDescription` is set through `INFOPLIST_KEY_NSCameraUsageDescription` in the app target build settings. No entitlement changes: the sandbox already allows user-selected read-only files, which covers the importer, drops and the pasteboard.

## Migration

There is no `VersionedSchema`; the store relies on SwiftData's automatic lightweight migration and CloudKit's additive-only rules. This change only adds:

- A new entity `Attachment` whose attributes are all defaulted or optional, with no unique constraints.
- One optional to-many relationship `Transaction.attachments` with the explicit optional inverse `Attachment.transaction`. Existing transactions migrate with no attachments and nothing is rewritten.
- `data` uses external storage, which CloudKit syncs as a `CKAsset`; `data` can therefore be `nil` on a device until the asset has downloaded, and the UI skips such attachments rather than deleting them.
- In CloudKit this is one new record type (`CD_Attachment`). Deploy it from the development schema to production in the CloudKit Console before a release build reaches users. Older app versions ignore the new record type and keep syncing.
