# Phase 17 — Auto-Categorization with Apple Intelligence

Suggest categories on device with Apple's FoundationModels framework. There is no fallback: without Apple Intelligence the feature is off everywhere.

## Implementation guide

- **Service** (`Helpers/AutoCategorizer.swift`): everything that touches FoundationModels is behind `#if canImport(FoundationModels)` and `if #available(macOS 26.0, iOS 26.0, *)`, so the macOS 14 / iOS 17 targets are unchanged.
  - `availability` maps `SystemLanguageModel.default.availability` (`deviceNotEligible`, `appleIntelligenceNotEnabled`, `modelNotReady`) to `.available` or `.unavailable(reason)` with a one-line reason; older systems get a generic reason. `isActive` = available and the `autoCategorizeEnabled` default (`AutoCategorizer.enabledKey`, on by default). Every entry point checks `isActive`.
  - `History` counts category use per `TransactionMatcher.normalizedTitle`. `category(for:among:)` returns the most used category among the allowed candidates, ties broken by the most recent transaction.
  - `modelSuggestion(for:)` opens a fresh `LanguageModelSession(instructions:)` per title and calls `respond(to:schema:options:)` with a `GenerationSchema` built from `DynamicGenerationSchema(name:anyOf:)`, so the answer can only be one of the candidate category names or `None`. Sampling is greedy. The answer is mapped back to a `Category` by case-insensitive name; `None`, an unknown name or any thrown error means no suggestion. Title, details and amount are passed as quoted, single-line, length-capped data fields and the instructions tell the model never to follow them.
  - `suggestion(for:history:)` is history first, then the model. `resolve(_:history:onProgress:onResult:)` runs a batch sequentially, caches by normalized title + candidate set so each distinct title reaches the model once, stops when the task is cancelled, and skips items without a suggestion.
- **Settings** (`Views/SettingsView.swift`): the "Auto-Categorization" section has the toggle (disabled and shown off with the reason in the footer when unavailable) and, only while active, "Re-categorize this month…".
- **Add form** (`Views/TransactionFormView.swift`, add mode): `.task(id: title)` waits 700 ms after the last keystroke, then asks for a suggestion among all categories when the title has at least 3 characters and the user has not picked a category. The picker goes through `categorySelection`, which marks `categoryPicked`; picking a title suggestion does too, and the flag is stored in the draft. An automatic pick shows a sparkles caption under the picker and is never applied after a manual pick.
- **CSV import** (`Views/CSVImportView.swift`): the review opens as before. The "Categorize with Apple Intelligence" button runs `resolve` over rows whose category still equals `ImportDraft.assignedCategoryID` (the last automatically assigned one), so rows the user changed are left alone. Candidates follow the row's direction (`isInflow`): income or investment for money in, expense or investment for money out; an investment pick sets `isInvestmentReturn` from the direction. Progress and Cancel replace the button while it runs, and filled rows show a sparkles mark.
- **Bulk re-categorize** (`Views/RecategorizeView.swift`): covers current-month transactions that have a category and no `recurringRuleID`. History is built only from transactions before the current month, and candidates are the categories of the transaction's current type. Only rows whose proposal differs are listed, with checkboxes (checked by default), Select All / Select None, Stop, and Apply / Cancel. Nothing is written until Apply.
